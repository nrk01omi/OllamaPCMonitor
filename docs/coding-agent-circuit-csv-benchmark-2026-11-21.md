# コーディングエージェント比較: サーキット走行 CSV ビューア

2026-11-21 に、GLM-5.3-Flash、DeepSeek-V4.1-Flash、Qwen3.8-Flash-Nextへ同一の課題を与え、実装・ブラウザ検証までの挙動を記録した。

## 課題と条件

- 入力はユーザー提供のDrogger走行CSV（9,082,521 bytes）。SHA-256: `70A1F28625AA852F97570891F1FA69DDE830199AF6E52605F5E2C60752182C2B`。
- CSVはヘッダーを除いて89,884行、Lap値21個、GPS有効行89,880、無効座標4行。
- 390px幅のスマートフォン向け、ブラウザ内でCSVを読み、Lap選択・速度色分け経路・統計・プライバシー表示を持つ静的アプリを作る。
- 各モデルに同一README/CSV、空の個別作業ディレクトリ、同じツール群（list/read/search/write/run browser test）、temperature 0、最大8,192 tokens/応答、最大24ラウンドを与えた。
- 計測時間はrunner開始から最終応答まで。モデル起動・ready待ち時間は含まない。タスクのコードは一時ディレクトリに保存し、プロジェクト製品コードには取り込んでいない。

## 結果

| モデル | 実装時間 | ラウンド / ツール呼び出し | 結果 |
|---|---:|---:|---|
| GLM-5.3-Flash (Maya-XS 128K) | 67.7分 | 24 / 32 | 3ファイル生成。エージェント内テスト8回すべて失敗、最終報告なし。独立ブラウザ確認では画面・21 lap・Canvas経路・速度統計が表示されたが、行数と無効行数が各1過大。 |
| DeepSeek-V4.1-Flash (Maya-XS 64K) | 62.2分（再開runner） | 5 / 8 | 読み取り・検索のみ。コードファイル作成とブラウザテストなし。空の最終報告で終了。完走失敗。 |
| Qwen3.8-Flash-Next (Strata IQ3_XXS 128K) | 9.3分 | 24 / 28 | 3ファイル生成。エージェント内テスト6回すべて失敗。モバイル表示と統計欄は作ったが、診断用の偽Canvas/統計コードがHTMLに残り、読み込み中表示も画面に残った。完走基準は未達。 |

### GLM

- runner記録: 663,202 prompt tokens、60,482 completion tokens、テスト終了コード `2` が8回。失敗内容は30秒待機タイムアウト6回、Canvasの `px is not defined` 1回、ファイル入力欄なし1回。
- 独立ブラウザ試験では、実CSVから21 lap、89,880有効GPS点、速度統計、Canvasを確認。ページエラー・外部通信・横はみ出しはなかった。
- ただし表示値は89,885行・5 skipped（実際は89,884行・4 skipped）。CSVヘッダー行をデータ行として数えている。全有効GPS点89,880は正しく表示。
- UIはカード型でモバイル画面に収まり、ラップ選択・速度凡例・開始/終了マーカー・プライバシー注記を備える。

### DeepSeek

- 最初の2回の長い応答は約1,799秒で `cancel=True`。runnerのHTTP timeoutが1,800秒だったため、タイムアウトによる打ち切りと判断できる。会話中断と時期は重なったが、ログ上の直接要因はrunner側上限。
- timeoutを7,200秒に延長して再開後、runnerは約62.2分・5ラウンド・8ツール呼び出しで終了。ツールはlist/read/searchのみでwrite_file/run_testsは一度も呼ばれず、`final_text`は空。
- この実行でアプリ品質を評価できる成果物はない。生成速度の参考として、初期の長いthinkingは約3.9〜4.3 tok/s。これはこの実機・量子化・Maya設定での単一runの観測値。

### Qwen

- runner記録: 690,635 prompt tokens、51,314 completion tokens。テスト終了コード `2` が6回。すべて固定テストの「89,884行かつ89,880有効GPS行が画面に出る」待機が30秒でタイムアウト。
- 独立した条件変更テストでは21 lap、Canvas、速度凡例、横はみ出しなし、外部通信なし、ページエラーなしを観測。ただし「有効GPS合計89,880」の表示がなく、選択中lapの点数と無効GPS件数のみ。
- 生成HTMLに診断用の合成データ生成スクリプトが残り、Canvasへ仮の対角線を描いて `window.__loaded=true` とする。これによりreadyフラグだけを使う試験は誤って合格し得る。実際の30秒後画面にも「Parsing rows…」と「Loading file…」の表示が残った。
- CSSでは `.loading` と `.track-empty` に `display:flex` を指定しながら `[hidden]` 用の上書きがない。HTMLのhidden状態を画面表示へ反映できず、読み込み中の表示が残る原因になっている。

## 比較上の読み方

- このお題では、Qwenが最も短時間でUI一式を生成し、GLMは独立検証でCSV処理・経路表示まで確認できた。一方、どちらも指定テストを通して完走したモデルはない。DeepSeekはこの設定でコード作成に進まなかった。
- 時間差にはモデル性能だけでなく、異なる実行基盤（Project MayaとStrata）、量子化、長いthinking、反復テストが含まれる。単発の比較結果で一般的なモデル能力を断定しない。
- runnerの厳格な表示値チェックは、モデルが合計有効点数をUIに出さない場合に失敗する。ただしGLMの1行ずれ、Qwenの診断コード/hidden表示問題、DeepSeekの未実装は独立確認でも観測された。
- 前提アプリのソースはローカル検索で見つからず、3モデルとも既存アプリ改修ではなく共通仕様からの新規作成。
